# Retained browser sessions and per-area publication

The ordinary browser entry uses the retained native campaign for local runs, Mu, Continue and local co-op. A hosted WebRTC session uses the same campaign, with one authoritative frame and recipient-specific publication from each player's actual area.

## Hosted delivery

The browser caches NativeHostedPublication by the installed NativeClientRuntime and current NetTransport. Joining and reseating reset delivery history before the existing-seat early return or newRun message. Terrain precedes the corresponding state, including when an existing channel gets a fresh render shell. The original global zone broadcasts are bypassed for retained campaigns.

Recipients come from connected non-host peers and the actual campaign roster. The finite serializer groups them by registered physical area and uses that area's real controllers and stores. It never swaps the writer's published scene to serialize another player. A retired or unready registered runtime refuses publication; it cannot select the original World serializer as a fallback. Existing metadata heartbeat recovery remains in place.

The targeted transport reports acceptance per seat. A skipped terrain send prevents that recipient's state send until terrain succeeds. Native partial query and send effects remain observable, and metadata clearing follows the publication attempt.

## Saved local co-op joins

A saved guest selection captures the joining run, local transport, ceremony generation, controller claim and actual roster card. Closing or reopening the ceremony, a newer pick, controller loss or a run replacement expires the old selection. A delayed result cannot mint a guest in another run or close a newer ceremony. Card removal, replacement, falling, slot changes and mismatched returned vessels are checked before native seat creation.

The existing saved-loader mirror refresh and native mint, graft and persistence ordering remain intact. Cancellation does not roll back writes already made by the original save loader.

## Online entry lifetime

Automatic return, explicit online entry and a server-bound wake carry the same selected entry generation across their saved-vessel reads, solo-world confirmation, connection and loading-cover awaits. A newer entry revokes a pending connection. Late failure cleanup can close only the old transport and cannot reset a replacement run. Successful shell adoption consumes the pending entry before adoption intentionally advances the generation.

The original post-hydration delayed character-read regression remains available alongside the expanded lifetime browser course. It requires the new local prologue to stay active and the stale return to make no socket attempt.

## Verification and remaining scope

The durable browser courses are balance/native-hosted-browser-ui.cjs and balance/native-couch-join-ui.cjs, with their Node runners. They use actual UI joins, real local WebRTC handshakes, real disk-read delays, retained admission, native travel and client render shells. Hardware input uses the existing indexed fake-pad boundary. The hosted course must use a built game; HOLLOW_WAKE_UI_DIST selects an isolated build.

Continue, local input, hiring, party death, dimensions, startup cancellation and historical source proofs remain mandatory adjacent checks. Frozen predecessor source archives and original assertions are preserved through exact bounded composition readers.

The acceptance order is content and mechanic parity with main, followed by the shared Shard world. The intended online destination is a server-authoritative landscape shared by multiple players, with explicitly separate quest, event and side-area instances where their content requires it. Browser-hosted delivery supplies reusable recipient and area-isolation checks; it is not the target multiplayer architecture.

The residual local-content audit has found a free-sailing transition gap: the voyage record remains on the departure area after entering voyage_sea. Instant port travel coverage does not prove free-voyage, landfall or Wraithsail parity. Close that gameplay lifetime gap before advancing the Shard campaign conversion.

This browser integration does not convert the dedicated ShardHost/SimUnits authority to retained campaigns and does not claim full server parity. Navigable bounded/open places, terrain barriers, hierarchy and map zoom follow completed runtime parity. Generated private quest and event entrances retain the requirements in [Generated quest side zones](generated-quest-side-zones.md): instance ownership, filtered visibility and collision, durable placement, objective/reward state and a safe return route.
