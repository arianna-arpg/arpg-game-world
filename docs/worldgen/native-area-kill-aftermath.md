# Native kill aftermath construction

`NativeAreaSceneKillAftermath` shares three unchanged native World methods: `rollKillOrbs`, `rollKillRemnants`, and `spawnDeathBurst`. It creates resource records after a caller has selected a kill recipient or a dying actor. It does not perform kill attribution, damage, death processing, pickup collection, burst ticking, actor retirement, or retained runtime publication.

The owner uses its actual retained scene, geometry, loot sink, campaign and actor authority. Each actor-reading entry requires exact physical membership, an admitted census, and the same registered aftermath, loot and geometry owners. Dead actors remain valid while physically present. A hidden carried body is refused; its actual controlled form is valid. Coordinates and numeric actor IDs cannot substitute for body identity.

Orb rolls use the existing loot owner's raw orb queue and `shedOrb`. Remnant construction uses the actual local geometry's `clampPos`. Selected callbacks are read lazily and invoked with their original provider as receiver through `Reflect.apply`; a callback's own `apply` property is irrelevant. Descriptor-proven construct exits may omit prey admission only after the physical caster has been validated. Accessor-driven ambiguity requires admission and then runs the untouched native body.

A fresh explicit state holds the exact raw `remnants` and `deathBursts` arrays. The existing reward-storage registry now also names these two slots, so its seven slot families reject initial, later, historical, cross-slot and cross-owner aliases. The runtime registry algorithm is unchanged. Slot enumeration, supplied array identity, native methods and same-slot historical reassignment remain intact. Frozen raw arrays are allowed: a native push fails at its original point after preceding reads and random draws. Constructor failures consume neither state nor arrays.

A later combat controller must route those operations through these same stores. This tranche does not install those writers or readers, and does not claim protection for arbitrary shared individual records or queues owned by other registry families.
