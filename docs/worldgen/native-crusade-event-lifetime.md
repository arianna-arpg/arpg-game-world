# Retained Crusade event lifetime

A retained area's native Crusade guard now follows the actual overlay event object. The shared native registry and garrison birth bodies remain unchanged. A new event can materialize its own garrison once; repeated frames and returns keep the existing bodies, wounds, rewards, terrain, and gate lifecycle.

The retained owner observes the real birth operation and actual population factory. It records the event as spent when the native per-zone guard is committed, including when later native callbacks fail. A partial native birth therefore keeps its original effects and cannot replay its ledger or garrison. Reconciliation runs inside the existing physical operation and rechecks selected field, marker, census, and owner identity around callback-capable steps.

Each native-created commander carries its issuing event identity. An ended event's commander keeps ordinary monster death effects but cannot claim another event's liberation reward or suppress its successor. A still-live older campaign is resolved through a bounded field receipt for that exact event, even when a different campaign now dominates the same area. Selected callback replacement, expired event identity, and repeated resolution cannot redirect the receipt to a new event. Unbound original World kills retain their prior package handler behavior.

Verification includes `nativecrusadeepochwitness` (actual first and successor realm bosses and a genuine departure/return), `nativecrusadeoldcommander`, `nativecrusadecommanderparity`, and `nativecrusadeepochboundaries`. The latter covers same-event retention, actual remote Seat occupancy, current and stale commanders, selected queries and marker operations, native partial notice/birth effects, and a selected kill callback replacing the event. The current-commander comparison requires exact field changes, XP, and drop counts; it records initial body differences caused by the fixture's additional retained birth separately. Event staging uses the supported overlay development entry point; boss kills use the actual native kill operation, not natural combat. Remote occupancy is actual retained Seat/road behavior, not new TCP or browser acceptance.

This repair preserves existing terrain. The separate phase142 terrain receipt confirms that, after a distinct second event, original World builds Crusade works while the warm retained area does not. Safe renewal of walls, doors, structure occupants, walk grids, and destroyed or opened objects remains open; generic layout adoption would erase unrelated warm state. Same-event tier changes, broader content parity, actual Shards transport acceptance, and 60 Hz capacity are not established by these finite checks. Original source assertions, archives, roster, and CLAUDE instructions remain unchanged for integration review.
