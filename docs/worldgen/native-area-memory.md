# Native area memory

NativeAreaMemoryRegistry lets the genuine campaign character writer capture the
state of each registered, born and physically admitted native area. It shares the
original World memory rules through NativeSceneMemory and reads the area's actual
actors, physical contents, objectives, occurrences, harvest, openings and puzzles.
Registration grants no scheduling, publication, departure or retirement authority.

## Identity and save behavior

The owner retains its exact source definition, area ID and surface/cave namespace.
Readiness checks require completed birth, the activated physical-presence owner,
and the same actor-authority binding. Matching IDs, coordinates or accounts alone
do not establish ownership. The writer must have completed the actual World
constructor; prototype imitations and failed construction refuse registration.

Serialization captures a stable cohort of registered owners once before assembling
memory rows. Each successful row immediately replaces its previous memo, retaining
native partial mutations if a later capture throws. The exception refuses the
character write. The current area uses the captured row from that same pass, so
an older World scene cannot overwrite its actual retained owner's contents.
Without registrations, existing native save ordering and skip rules remain intact.

Registration and capture reject reentrant registry operations. Source identity,
namespace, campaign stores and authority must still match on every capture.
Unregister captures a noncurrent area's final cold-memory state, then removes the
observer. The current writer area refuses unregister before capture or map mutation
until the real writer has handed off that scene. This is not a retirement API.

## Evidence and limits

The nativeareamemory probe covers original/shared/World/retained snapshot equality,
objective riders, copy isolation, live replacement of physical arrays, skip rules,
immutable source identity, real writer identity, exact presence authority, duplicate
owners, reentrancy, capture-once behavior, stale-current-scene protection and native
partial failure. Its lifecycle course proves that refused current unregister leaves
the registration and memo untouched and a later save captures actual area content.

The save course uses the real saveCharacter and saveCharacterDurable APIs, reads
resume authority, stages Continue, and performs two fresh complete native births.
It checks exact restored contents and survivors, completed-objective reward latches,
stale-Continue rollback, noncurrent unregister and native memory expiration.
Storage is a same-process in-memory localStorage mirror. This does not establish
disk or browser-restart durability, actual cave birth, multi-area campfire/departure,
transient combat checkpoints or production runtime publication.

The historical fixture reverses only byte-checked delegates, imports and writer
integration, preserving the original World receipt. It does not accept arbitrary
source changes or repin gameplay/balance baselines.
