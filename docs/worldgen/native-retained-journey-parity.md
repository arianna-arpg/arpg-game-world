# Retained journey content parity

The seamless browser campaign keeps visited areas alive. Content that originally relied on `World.loadZone` rebuilding an area therefore needs an explicit arrival or episode-lifetime operation. This integration closes the bounded bounty, voyage, realm and delayed package-fixture paths described below. It does not certify every feature on `main`, activate dedicated Shards, or add general save migration.

## Bounties accepted after exploration

A genuine return to the destination runs the existing Cull mark, Gather node and Trail arrival rules using that retained area's continuing layout RNG and actual points of interest. New marks are admitted through the real factory and combat owner. Existing monsters, harvested nodes, drops, doors and objective state remain alive. Repeat arrivals do not replace remaining targets or grant duplicate rewards.

The gameplay courses complete three actual Cull postings, a naturally unlocked Gather and a naturally unlocked Trail; they check partial completion, wrong-order travel, turn-in rewards and repeat visits. The cold course starts a separate process from genuine saved bytes, restores the already visited destination through recorded Continue, accepts its posting in town and completes it. This particular course does not prove HTTP or disk transport; the existing Continue transport courses cover those separately.

## Voyages and boarding

The actual local crossing carries the exact voyage and boarding stash into the destination. Distinct destination runs, late substitutions and foreign cohorts refuse before transfer. Returning from a boarded ship resumes the retained sea using the same native arrival fragment as first birth.

A completed unoccupied sea retires after the enclosing operation unwinds. The next voyage can then create a fresh sea despite the constant `voyage_sea` identifier. Retirement preserves campaign-wide deed callbacks and refuses late cohort or census changes. Only that exact retired sea can be skipped by an already captured frame roster.

Real courses cover natural dock dwell, landfall, a second voyage, the Wraithsail deck/hold/Regent cabin return chain, abandonment and callback failures. Existing off-graph save policy remains: Continue from a voyage or boarding save wakes in town. These voyage Continue courses run in one process and make no additional disk-durability claim. Existing hosted sailing restrictions remain.

## Realm entry, completion and return

The Demon, Crusade, Necropolis and Fracture plans issue their context to the actual destination before layout and birth. Their bosses, garrisons, ward guards and Demon Storm records use the existing native creation and admission boundaries. Native kill rewards and completion effects belong to the realm that owns the encounter.

Leaving an unfinished retained realm and returning preserves its wounded boss, crowd and partially broken wards. A private receipt binds the exact area, definition and prior context; arbitrary replacement refuses. Reentry skips an already consumed first-wake operation, and a completed context cannot create a new boss or reward.

The real courses compare original, solo retained and hosted entry/completion for all four plans. Kill-boundary drops use an explicitly shared seed; whole-journey RNG equality is not claimed. The original Crusade return-to-surface course encounters a real generation failure, preserved as an oracle limitation rather than hidden by resampling. The retained warm-return course succeeds with its existing layout.

Surface effects preserve voyage abandonment before defeated-Necropolis culling. In retained travel these effects occur after departure memory capture and before destination preparation. A callback still observes the source as published at that boundary; a destination that has not been prepared is never published early. This is an explicit retained phase policy, not a claim of identical `World.loadZone` callback timing.

## Delayed package fixtures

A package feature that unlocks after a cellar was first visited must appear on a later genuine arrival. The bounded furnishing path installs missing supported structures through native generation and real entrance registration while retaining the area's live stores. It does not rebuild the full area or silently support arbitrary actor-, door-, reward- or topology-changing plans.

The concrete regression is a purchased Pit whose level requirement becomes satisfied after the first cellar visit. Its actual mouth must appear once; nested entry, level updates and return must continue to use the real ladder and retained owner.

## Verification and remaining gate

Focused probes use the `nativebountyarrival`, `nativevoyage`, `nativerealm` and `nativesidezonefurnish` prefixes. Combined validation must also include retained combat/frame, hosted travel, Continue, installed-source and generation checks, all four type-checks and relevant browser/boot coverage. Historical source archives retain their original assertions; a strict outer composition reconstructs the reviewed parent inputs.

Several cold-process harnesses now resolve their own module and the installed `tsx` CLI instead of assuming a scratch-directory depth. Temporary save bytes stay under ignored `balance/reports`. Their original gameplay assertions remain intact.

The broader content audit has identified Odyssey siege birth/admission failure and a missing Nemesis survivor scan on departure. These remain separate content-parity blockers. Dedicated ShardHost conversion, same-landscape multi-player server authority and deliberate private quest/side instances follow the content gate. Co-op infrastructure is reusable support, not the destination architecture.
