# Recorded native dimension catalogs

`new NativeClientStart(account)` captures the installed native geography once and records a catalog for every captured registered dimension. Supplying an existing `MassNativeMapping` keeps the original single-mapping path. Browser/main integration is separate; no fixture mapping is a production default.

The catalog has its own schema/version and coordinate policy, `native-chart-unit-address-v1`. A durable address unit is one native world-map chart unit. It does not mean one actor pixel or one metre, and does not resize any area's arena. Binary pages of 1024 chart units partition addresses for storage. Each native dimension has a separate physical dimension with the same recorded identifier, native/physical origins at zero, and exact scale 1/1. No modulo, wrapping, clamping, recentering or reroll occurs.

The coordinate envelope is derived from the exact captured source. Its symmetric bound is the floor of the minimum of 2^52 and each actual field/continent/noise lattice span times (2^52 minus its search margin), minus the largest coastal probe. Margins reserve field search plus four cells, and five cells for continent/noise stencils. The 2^52 chart cap retains unit resolution in binary64; it is not an assertion that every point inside the envelope can execute. The unchanged native geography reader still checks every actual point, derived lattice index and distance and refuses unsupported arithmetic. Nonpositive or unrepresentable derived envelopes refuse creation. Exact rational source anchors preserve generated coordinates that cannot round-trip through a binary64 physical offset.

Catalog entries preserve the captured dimension order, exact source JSON bytes, full mapping and existing checksums. Missing, duplicate, foreign-source, reordered or conflicting entries refuse. The reader reconstructs each production mapping from its recorded source and policy. Each selected geography instance is frozen as well as its specification. Runtime and preparation retain those canonical catalog entries, so later writable aliases cannot replace a validated mapping. Destination preparation selects the actual definition's dimension. `NativeAreaSourceSession` keeps its original strict dimension, installed-source and definition identity checks.

Save envelope version 2 records the complete catalog, manifest, character identity and complete native world fingerprint. Continue reads only saved entries; it cannot capture current geography to fill an omission. Version 1 keeps the original single-geography reader/writer bodies and does not silently migrate. A malformed envelope refuses before staged account publication and preserves the old save. Both versions retain genuine storage leases, staged account checks, native partial effects and the existing companion/throng restoration lifecycle.

Verification includes real default starts, underworld/aetherial entry, retained same-town return and dimension revisit, exact source anchors, malformed save/account refusal and retry, and real launcher disk saves restored in independent processes with empty mirrors. Existing v1 Continue and the original unsupported single-mapping dimension control remain unchanged. The original return/revisit course uses the genuine coordinator transfer entry; an additional course resolves actual native threats and uses the original waypoint travel action to return from both realms. This does not claim every authored realm exit mechanism has been exercised. Browser wiring, per-recipient networking and a metric relationship between chart coordinates and area-local arenas remain separate.
