# Retained Verminfall event lifetime

A completed infestation can naturally return to farmland that is already retained.
Previously the zone's once-only materialization marker survived the first event:
the successor claimed the field and increased town pressure, but created no nests.
The preserved seed-1211 reproduction reached a natural second event requiring two
nests; ordinary World created two and the retained area created none.

The retained owner now associates placement and event bodies with the actual
issuing infestation object. Same-event visits retain bodies, wounds and completed
placement. A successor reconciles only its infestation marker and receives one
native placement. Surviving vermin, unrelated bodies and other package markers
remain. Remote occupancy does not turn an old event's bodies into a new event's
nest or king. The ordinary unbound World path keeps its original calls.

The owner captures the actual overlay's projection and mutation helpers, actual
combat entry/hooks, and population construction receipt. Selected query, field,
factory and insertion operations are checked before selection, before invocation
and after invocation. A successful factory result must have been constructed by
that invocation; an earlier unused body is insufficient. A copied package tag
cannot authorize an unbound retained body's event payout.

Completed native effects survive exceptions. A successful marker add consumes
placement at the marker operation itself, even if a later selected factory deletes
the marker and throws. Any nest already inserted and admitted stays present; the
next live pass cannot replay the consumed placement. A nest death and completed field decrement
remain when king spawning throws; warm visits do not retry that consumed birth.
If the selected spawn inserts and admits a king but throws before returning, that
partial body remains without fabricated event ownership. A later copied king tag
cannot clear the armed event. A genuine king clear may finish its original
reward/notice after ending its own epoch, once only. An active field mutation
scope cannot be replaced by a nested public scope: a selected resolver that
replaces the event retains that completed replacement but cannot advance its
successor through the old body's kill.

The historical direct Crusade live-registry entry still composes through the
actual Verminfall owner. A private synchronous recognition scope prevents a
second registry invocation and does not grant authority to method getters or
reentrant callers. No caller-supplied readiness flag is accepted.

## Persistence and verification

No save schema is added. Warm returns preserve resident bodies. Actual disk
Save/Continue reconstructs the durable remaining nest count or armed king through
native cold birth, with fresh body health and the existing discovery ledger.
Transient event bodies remain subject to the existing serialization rules.

Standalone courses are kept outside the sealed historical probe roster:

- check_nativeverminfall.ts: original/retained natural first and successor events,
  warm wounds, actual package XP and normalized minted reward payload comparison.
- check_nativeverminfallboundaries.ts: selected callbacks, stale bodies, partial
  writes, actual remote Seat occupancy/roads, registry composition and reentry.
- check_nativeverminfallcold.ts: isolated launcher disk saves and fresh-process
  original/retained Continue for remaining nests and an armed king.
- check_nativeverminfallsource.ts: finite exact predecessor reads, byte equality,
  mutation/descriptor controls and unchanged archive inventory.

The natural comparison passes first and successor events, with 540 package XP
and three identical normalized memory rewards per king in both lanes. All 33
boundary cases are preserved, with additive checks for marker deletion after a
real partial birth and attempted nested-scope replacement during a genuine nest
kill. Actual isolated disk Continue passes for two remaining
nests and for an armed king in both original and retained fresh processes. Each
child loads the exact persisted account and starts from identical frozen account
and character bytes. Expected cold bodies and fresh health are asserted before
an explicit live-registry recheck, which must preserve their exact identities.

All four type-check lanes pass. These courses use disclosed fixture shortcuts: skipped prologue, staged level/invulnerability,
direct native travel/kills and wounds, isolated overlay clock, and explicit
callback replacement only in fault cases. Remote occupancy uses real Seat and
road owners; it is not a TCP/browser multiplayer acceptance course. Package reward
comparison fixes only the package row RNG and excludes item UID/drop position.
No full-content, private-instance, capacity or performance acceptance follows.

## Performance boundary

The lifetime wrapper currently adds a raw actor-descriptor copy and physical
ownership entries to each live-registry pass. The pass runs once per retained
area per completed simulation frame, including areas with no occupants. Before
the existing Crusade work, the wrapper makes four ownership entries; a present
Verminfall field adds three query checks, and a consumed active event adds one
placement check. Each ownership entry includes validation on exit as well.

This is additional work on an already over-budget retained runtime. The counts
are source observations, not measured timing. Reducing duplicate checks requires
proof that the intervening reads cannot invoke selected code; no census result
may survive a callback or replace the current raw physical validation. The joint
performance lane is reviewing that composition separately. This parity change
establishes no speed improvement or frame-budget acceptance.
