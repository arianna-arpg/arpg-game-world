# Native ground fields and follow-up construction

NativeAreaSceneGroundFollowUps owns six native preparation operations:
maddenBankOf, mintAftermath, dropLingerField, mintTrailPatch, statTrailSpec and
queueFollowUps. The shared core also contains the unchanged flattenPulseQueue
helper. This is record construction on actual progression stores, not field
advancement, damage, full casting, actor retirement or retained publication.

The owner reads the local progression owner's actual zones and pendingFollowUps
queues and the live campaign time. Follow-up construction selects the real
casting-preparation owner's mintMetaInstance method lazily and invokes it with
its original receiver. It retains native record references, RNG consumption,
queue replacement, exception timing and partial writes.

Actor-reading entries require the exact physically present caster, registered
scene, ground owner, progression owner, casting owner, restoration/tether owners
and campaign ledger. Admission is checked again after the last campaign seats
callback, without another campaign callback. Preparation-time borrowed observers
and a caster transferred during validation cannot write to the former area.
The actor-free trail-spec calculation remains pure. Madden-bank selection has
no caster argument, so it requires the actual registered owner and admitted
census rather than inventing a physical subject.

## Shared skill credit

NativeAreaMaddenLedger owns one actual WeakMap for a campaign/session. All areas
in that campaign use that same ledger. A second campaign ledger, including one
constructed with a different authority for the same campaign, refuses. A raw map
cannot be claimed by another campaign. Ordinary input validation finishes before
any ownership claims, so a failed constructor consumes neither campaign nor map.
Nominal construction provenance prevents an object with a copied prototype from
claiming to be the actual ledger.

The native maddenBankOf body preserves SkillInstance identity. Removing and
restoring a compatible socket follows native behavior; changing its after value
replaces the bank exactly as the native body does. The supplied WeakMap remains
raw: selected own or inherited get/set methods retain native receivers, read
order and partial failures. The session ledger is not reset per area or per
field. This is in-memory ownership, not a new disk persistence format.

A field expiring in one area must not erase live credit belonging to an actor
in another. Only the native expireZone host view uses the authority's campaign
physicalActorById lookup. All other progression lookups retain the original
local runtime receiver. The new lookup examines actual registered, fully admitted
physical censuses; ambiguous IDs and unowned census entries refuse. It does not
invent an alive-only filter or count a hidden carried husk as a physical body.
The native expiry body decides whether dead/absent entries should be pruned.

This lookup may fail after native refund or cue writes. Those earlier effects
are deliberately retained. The proof exercises actual carried transformation,
physically retained dead bodies, duplicate IDs, unadmitted neighbors and native
failure timing. Restoring the old progression owner in a separate negative copy
reproduces the specific bug: local field retirement deletes neighboring live
credit.

## Evidence and activation boundary

The immutable owner-only package compares original native bodies, shared core,
original World methods and the retained owner across 538 cases, plus nine real
ownership groups. Its original-World algorithm lane explicitly mirrors stores;
it does not prove that ordinary World delegates the new core. All six method
bodies and the pulse helper match the fixed main reference ea56c7ac. The owner
source proof reverses only declared exact owner changes and retains mutation
refusal checks.

The separate integration successor makes ordinary World delegate the same six
bodies through a cached, nonenumerable live adapter and imports the shared pulse
helper at its existing call sites. Its separate ordinary-World courses check
live queues/maps and selected receivers, native partial failures and real dormancy
dependencies. Exact source reversal binds the complete World to the committed
42f95716 baseline. The frozen integration preserves all 538 native cases and
nine ownership groups and passes seven ordinary-World groups. All four type
configurations and the affected casting, defense, kill, progression-storage,
installed-source and visual-source guards pass.

The original 98 main-visual hunk controls operate on their exactly reconstructed
visual source through an explicit visual-only normalizer. The public current-source
normalizer reverses ground integration first, then visual integration. A separate
raw-World proof mutates and duplicates all ten new integration hunks and verifies
that unrelated edits survive both layers for historical guards. Removed method
bodies are not counted as raw mutation targets. The original owner-only freeze
remains unchanged. Neither package supplies the complete recursive combat controller,
ground/follow-up ticking, detached source authority, scheduler, map handoff or
whole-area publication and persistence.

The next milestone is a real aggregate that composes these construction services
with casting, damage, kill processing and operation lifetimes. This must replace
the external combatFor requirement with a genuine area service; an active World
method driver in a test cannot establish that capability. Bounded/open navigable
places follow complete retained content ownership and publication.
