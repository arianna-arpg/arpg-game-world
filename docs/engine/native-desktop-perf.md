# Retained desktop performance course

The desktop sweep uses the actual retained client created by normal native
startup. The previous course stopped at its first legacy devTravelTo call with
"Native published identity cannot be reassigned: zone". That guard is unchanged.

src/dev/nativePerfTravel.ts invokes the existing deterministic development
mint/travel recipes against a finite receiver inside the real coordinator's
synchronous runFrom frame. Campaign zone definitions and generation IDs remain
campaign-owned; preparation, cohort transfer and center landing use the actual
retained coordinator. Destination zone and arena reads follow its current owner.
Failed operations keep the native partial effects already completed.

The course waits for account hydration and starts after the tutorial. It restores
and persists the exact previous tutorial gate, including when startup throws;
other genuine startup effects remain. It never clears gameplay holds. Walking
hazard checks read the actual current area's geometry and reject a stale owner.
A sample must contain completed frames, positive simulation time and commanded
walking distance, and no paused frames. A recorded fatal reports its original
message and stack instead of presenting stopped telemetry as zero-cost work.

The original tileset matrix, id-based seeds, variant/layout pins, weather,
walking input, entry/steady windows, retry rules and balance/perf.config.json
budgets are unchanged. Warm returns keep actual stores, residents and wounds.
Completed reports identify runtime as retained-native. Every row records
residentAreas, residentActors, worldSeconds, walkDistance and pausedFrames.

All resident areas continue to advance. Later rows and the aged town include
that accumulated cost; these are native campaign measurements, not isolated
per-tileset costs. Optional lite stress remains a separate diagnostic course.
The launcher's deadman reports retain their existing partial-report shape.
