# Main and seamless: historical comparison before player decisions

This is the comparison snapshot used to assign C/V/P/W/N row IDs on 2026-10-19. Its branch tips, defaults, “Review” labels and file inventory are historical. **Use [the current gameplay decisions](gameplay-decisions-20261019.md) for approved changes, reversions and pending choices.** Main has since received approved shared features; this table is no longer a current difference report.

Corrections discovered while applying the decisions: V07 floating-number avoidance and V13 ground-label avoidance helpers were not wired into the renderer. The claimed announcement collapsing was not implemented. V06 garrison/formation label helpers were also unused. The current record distinguishes these from visible features and documents the actual options now provided. P07's passive-list additions have been removed; V02's slot outline is now off by default; V14 uses animation rather than captions.

## What is aligned

The published content baseline is main `a2fa42917262e9229140b6364b6d5e461b32f50e`. It was already an ancestor of the seamless work being reviewed. Local main had copied patches and an older apparent tip; its history has now been reconciled through a real merge, preserving the published content tree and all unfinished root edits. Main `05847c85d531361f0a90c85bd71a37c15a18f08e` adds the approved integration workflow and policy, without changing that gameplay baseline.

Seamless was reviewed from `5fb883a488a9b47491b1bed2e4173a466812b399`, including the cast-bar correction in this alignment. Main is merged into it, not selectively copied. Future main pushes enter the [verified merge workflow](branch-integration.md). This is one-way integration: seamless-only gameplay changes do **not** become approved main content automatically.

Ancestry establishes inclusion, not identical final behavior. Later changes can still alter a shared system; those are the decisions below. A new filename is not proof of a new mechanic.

## How to use this register

**Restored** means the user's explicit revert is implemented. **Required** identifies the user's stated entry/world target. **Review** means an existing difference remains in place pending a keep/revert decision; it is not implicitly approved. **Infrastructure** identifies code organization or persistence work, not a new player feature. **Gap** identifies main content not fully delivered on the continuous surface.

Use the row IDs when choosing changes, for example “keep C04, revert V08.” Sources are repository-relative links. The [complete changed-file and named-function inventory](gameplay-alignment-files.json) includes every changed file under `src/`, `server/`, `launcher/` and `index.html` against the reconciled main baseline, with line locations and source fingerprints. It distinguishes added/removed declarations, changed bodies, and signature-only edits whose normalized bodies are unchanged. It deliberately contains no copied runtime source or new verification framework.

The inventory is complete at the file level. This table groups the behavior differences inspected in that source. It does not certify every extracted runtime function as equivalent: nested callbacks, registrations and changed dependencies still require their file diff when making a precise revert. The large retained-runtime migration remains an explicit review area (R01–R04), not a blanket claim of parity.

## Validation and next decisions

This alignment changes cast-bar dimensions and documentation/integration delivery. It does not rebalance skills, undo the current enemy changes, merge unfinished root generation work or port the missing campaign chains. The existing cast-readout check measures the restored bar's actual draw dimensions and cast clock, while the ordinary client playthrough exercises tutorial → Mu → continuous travel/combat → Save/Continue. Type checks, current behavior courses and the shared simulation/generation checks validate the merged baseline; they do not certify every Review row or multiplayer capacity.

The first useful choices are C01/C02 (input feel), C04–C07 (blink/enemies), V02–V18 (presentation) and P03/P08 (inventory/dialogue). Keep world delivery and ownership requirements distinct from those preferences. The next implementation should work from those explicit choices and W05's content gaps, with shared gameplay corrections made on main and merged forward. Rebuilding the combat/account framework from scratch is not necessary for this alignment.
